# M3 – Data layer, seed & audit core: evidence report

**Date:** 2026-10-02 · **DoD (plan §3 M3):** `db:reset && db:seed` idempotent; app DB role cannot UPDATE/DELETE `audit_event` (verified by test); hash-chain verifier passes and detects a tampered row.

## Built
- `apps/api/src/db/schema.ts` – Drizzle schema, 33 tables (all tenant-scoped except `tenant`). `migrations/0000_schema.sql` generated by drizzle-kit; `0001_integrity_security.sql` (+ `.down.sql`) hand-written: 38 foreign keys, value checks, least-privilege `app_user` role, append-only triggers (audit, approvals, contract delete), locked-contract guard, **row level security on `score`**.
- `db/client.ts` – PGlite + Drizzle; `withContext()` runs each request as `app_user` with identity as **transaction-local** settings; `withSystem()` for seed/jobs. `db/migrate.ts` – ordered runner, up / down-last / reset.
- `audit/audit-service.ts` – in-transaction, per-tenant sha256 hash chain, field-level before/after diff, redaction of sensitive keys at source, chain verifier.
- `http/idempotency.ts` – `Idempotency-Key` plugin (replay, reuse detection, per-user scope). `@if/shared` `Clock` / `ManualClock`.
- `db/seed.ts` + CLI (`npm run db:reset`, `db:seed`, `db:verify-audit`): synthetic "Meridian Group (demo)", **13 users** (one per role plus a second evaluator, needed for a variance scenario), 4 suppliers, 6 requests, closed tender with 4 bids + evaluation at consensus (one 38-39% flagged item), open tender, 2 executed contracts (one ends in 74 days), 6 notifications, 3 workflows, 4 templates, **49 chained audit events**.

## Defects found and fixed during M3
1. Seeded "38% variance" was actually 39.5% (chair's +0.2 offset skewed the maths) -> seed value adjusted; test asserts ≈38.
2. Drizzle wraps Postgres errors, hiding the message from naive assertions -> tests read `.cause`.
3. Parallel test runs exceeded the default 5 s timeout (each test migrates a fresh DB) -> 60 s timeouts.
4. Lint: loose `==`, unused assignment -> fixed. `package.json` formatting after scripted edit -> fixed.

## Not verified / caveats (honest)
- **No real Postgres here.** PGlite is single-connection, so true multi-connection pooling and concurrent writers were not exercised. What *was* proven: identity is transaction-local and cannot survive commit or rollback. A real-Postgres run (CI service container) is still owed and is scheduled for M17 hardening; until then the pooled-connection risk in Architecture §14 is reduced, not closed.
- Hash-chain writes serialise per tenant (tenant row lock); throughput under concurrency is unmeasured.
- RLS covers `score` only (as designed); bid-file RLS arrives with M8. Tenant isolation elsewhere is service-layer (`tenantId` on every query) and not yet enforced by RLS.
- `npm audit`: 4 *moderate* findings remain, all in `drizzle-kit`'s dev-time esbuild (affects a dev server we never run). Accepted; gate is high/critical. Will revisit when drizzle-kit updates.
- Seed password is a documented demo-only constant (override with `SEED_PASSWORD`); production never seeds.
- GitHub CI runs for M1-M3 remain unobserved by me (private repo, no `gh`).
