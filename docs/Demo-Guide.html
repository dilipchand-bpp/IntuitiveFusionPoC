1. What the app is

Intuitive Fusion is a source-to-contract procurement portal. A person describes what they need in plain language; the platform drafts the request, builds the procurement plan, runs a sealed tender with a supplier portal, supports a fair and auditable evaluation, drafts and signs the contract, then manages the contract for its life: spend, price control, alerts, variations and renewals. Every step is permissioned by role and delegation of authority, and every change is written to a tamper-evident audit trail.

The one-sentence pitch: "From the first sentence of a request to the last invoice against the contract, one platform, one audit trail, with approvals, probity and price control built in rather than bolted on."
  • Who uses it: 13 staff roles plus an external supplier portal (separate sign-in pool).
  • How it is built: Next.js 16 web app, Fastify API, PostgreSQL (PGlite locally, AWS-targeted), TypeScript throughout, one theme file, WCAG 2.1 AA checked on every screen with automated accessibility scans.
  • Proof it works: 771 automated API and unit tests, about 255 browser tests (each new screen has an accessibility scan), a 335-operation authorisation matrix that proves each operation is allowed for exactly the roles that should have it, and a delivery evidence document per milestone in docs/.

3. What is simulated or not built (say this before you are asked)

  • Simulated: AI (deterministic rules labelled rules-simulated-v1), email/SMS/Slack (recorded, not sent), single sign-on, ABN/vendor register, bank check, sanctions screening, ERP (purchase orders and invoices are entered in the platform), weather/financial/geopolitical feeds, public register submission.
  • Not in the proof of concept: items marked tier D in the requirements (for example multi-tenant SaaS operations, real e-signature provider, full ERP integration).
  • Still to do: M16 (documentation, runbook, demo script) and M17 (hardening: real-PostgreSQL tests, performance, Lighthouse).
  • Limits to know: a live tender cannot be closed in the room because the closing time is at least 25 days out; the demo therefore uses the seeded closed tender and the seeded evaluation (see Act 4).

4. Before the demo

Do this once, the evening before and again the morning of: a fresh database gives you the same clean story every time. Seed dates are relative to the day you seed, so seed on 6 Oct for the demo.
  • Stop any running dev servers. In the project folder run: npm run db:reset then npm run db:seed
  • Start the servers: npm run dev. Check that both http://localhost:3000 and port 4000 are listening (if sign-in says "Invalid email or password" for a correct password, the API is not running; restart npm run dev).
  • Use Edge or Chrome (voice dictation works there). Open two windows: a normal one for staff and a private window for the supplier so the two sessions never mix.
  • Pre-open tabs: sign-in page, /app/roadmap, docs/B6-Evidence.md (for questions).
  • Set the browser zoom to 110–125% so the room can read it. Check light and dark theme (sun/moon icon, top right).
  • Rehearse Acts 1–3 once end to end so you know where the buttons are, then reset and seed again so the stakeholders see the original seeded data.
  • Keep this page open on a second screen. Have the printed one-page run of show (section 6).
  • Do not run the browser test suite on the same machine just before: it uses ports 3100/4100 and its own database, but it is heavy.

7. The demo, act by act

Note: button names below are from the screens as built; if a label differs slightly on the day, trust the screen. Rehearse Acts 1–6 once before the audience arrives.

Act 0 – Opening 4 min

"This is a proof of concept running on synthetic data. Nothing here sends real email or calls real systems, and the screens say so."
ShowSign-in page: email and password, "Continue with single sign-on" (simulated provider), forgot password. Point at the banner "Proof of concept · synthetic data".
ShowSign in as the procurement lead. Note the left navigation grouped as Overview / Procure / Contracts / Insight / Collaborate / Oversight, the Jump to… search (Ctrl+K), the notification bell, the light/dark toggle and Preview on phone or tablet.
Say"Each person sees only what their role allows. An administrator does not even see the requests menu. Access is enforced on the server, not only hidden in the menu; there is a 335-operation test proving it."

Act 1 – Request intake 8 min

Sign in as the Requester (Riley Chen). Requests → New request.

1Type (or dictate with the microphone button in Chrome/Edge): "We need commercial cleaning for head office for two years. Around ninety thousand dollars. It's for Facilities."
2Watch the assistant fill the fields. Point out the "AI-drafted" marks and the "Simulated AI" label; answer its follow-up question for anything missing (contract owner, background).
3Edit one field by hand: it is saved and no longer marked AI-drafted.
4Submit. Open the request: the cards for process (workflow chosen by value), classification (UNSPSC), reviews needed with the reason for each, suggested suppliers, estimated contract value, and approvers.
5Optional: try a very large value to show the budget cap refusing it, or the "Move this procurement on" box: type "go to the next phase" and show it refuses because the plan is not yet approved.
"The assistant proposes, a person decides. Every AI-drafted value is marked, and it is rules-based in this proof of concept so results are predictable."

Keep this request: you will use it in Act 2 and 3. Choose about $90,000 so approvals stay simple.

Act 2 – Plan and approval 8 min

Sign in as Procurement (Priya Nair). Procurement plans → open the new plan.

1Show the plan: every section is pre-filled and marked AI-drafted. Edit a section directly.
2In the instruction box type "change paragraph 2 of the background to say the contract ends in June". Show the change, then Undo.
3Scroll to Working together: tracked changes, "since you last looked" digest, save a named version ("First draft"), later compare versions with additions and deletions highlighted.
4Open the request page: Risk assessment → Draft a risk assessment. Decide which risks apply, rate one, choose a treatment; Complete is refused until every risk has a decision.
5Back on the plan: declare conflicts of interest, then send for approval.
6Switch to the Delegate (Dana Okafor). Approvals → open the plan, read the key points, Approve. The plan locks with a stamp showing who, when and under which authority. Mention that on a phone this works too (use Preview on phone).
"Sourcing approval and contract signing are separate grants of authority. Holding one never implies the other."

Collaboration extras (1–2 minutes, optional): sign in as Administrator or Procurement → Collaboration: drag a section in the plan layout designer, save, show a new plan follows it, then Use the system default.

Act 3 – Tender and supplier portal 10 min

Procurement: Tenders → create the tender pack for your request (type RFP). It is staged: invisible to suppliers.

1Show the pack built from the plan (internal budget and risk wording is filtered out). Edit a section. Try the box Change the template: "use the request for quotation template"; sections you wrote are kept.
2Delegate: Approvals → give permission to publish.
3Procurement: publish with a closing time at least 25 days ahead (public-sector minimum), invite a supplier by email address. Email is simulated: copy the registration link shown on screen.
4In the private window open the link and register (ABN must pass the real checksum, for example 65 000 000 101), sign in, read the pack, ask a question, upload a technical and a commercial file and submit. Show the receipt.
5Back as Procurement: answer the question (the asker is never shown to others) and issue an addendum. Show that bids are sealed: files cannot be opened before close.
6Alternative if short of time: sign in as supplier@… who already has an open tender and a closed, submitted one; show their profile, insurance, banking details (only the last three digits echo back) and contacts.
"Nothing a supplier can see contains budget, risk ratings or who asked what. After the closing time uploads are refused by the server."

Act 4 – Evaluation and report 10 min

A live tender cannot close in the room. Use the seeded “Facilities cleaning services” evaluation (PR-2026-0001), which is already at the consensus stage. Running this act uses up the seeded evaluation; reset and seed again afterwards.
1Panel chair (Grace Mwangi) → Evaluations → open the cleaning evaluation. Show consensus per criterion and the one flagged score (37.5% apart): the chair cannot lock without a written reason.
2Show who sees what: sign in as Tomas Silva (technical evaluator) briefly: no pricing visible. As Probity (Jonas Becker): read-only view with the documents and a system hold control.
3Chair: enter the reason and lock consensus (the chair can reopen later with a reason).
4Procurement: open the evaluation → generate the evaluation report (sections: summary, compliance, ranking, scoring distribution, total cost, commentary, recommendation). Download the PDF. Show the supplier response summaries on the tender (pricing, dates, proposed changes, pros and cons; anonymous to panel members).
5Delegate: approve the report; it is stamped.
6Optional: Change the committee box on an evaluation that has not reached consensus: "add Nia", or a name that matches two people to show the picker.
"Scores are hidden from everyone but their author until the chair opens consensus; the database itself enforces it, not just the screen."

Act 5 – Contract award and signing 10 min

1Legal (Henry Albright) → Contracts. Under Awards ready for a contract the approved award appears. Click Draft contract: the template for the tender route (works vs services) is filled with the winner, value, dates and service levels.
2Edit a clause: it is marked Changed from template and listed under Deviations with a risk rating. Use explain this deviation (plain language with the corporate fallback), rate it in words, and show the negotiation strategy and risk summary.
3Run the checks: tender cross-check (price against what was tendered) and vendor pre-flight (legal name, tax, bank). A failed check blocks release until reviewed with a reason.
4Choose how signatures are collected (standard, blind, staged) and Release for signing. Show invited signatories, supplier reading and asking a question (supplier portal → Contracts).
5Delegate: open the contract, Sign contract. It becomes Executed and locked: no edit buttons, signature stamp shown. Above $1,000,000 an executive must also sign, and the demo executive holds no signing delegation, so keep the value under that.
6Show the two seeded executed contracts (CT-2026-0001, CT-2026-0002) as proof that locked is locked.
7Optional: Legal desk (matters board with review hours and the knowledge base) and, as Procurement, time-bound access for an auditor to one project's contract and report; Shared documents shows it ends by itself.

Act 6 – Contract management 12 min

Sign in as the Contract manager (Sofia Rossi) → Contracts → open CT-2026-0001 (Northstar Property Care, ends in about 70 days, with a 12-month extension option). Scroll to Managing this contract.

1 Overview"What to do next" suggestions (decide the extension, start a renewal), variation count, extensions used, cumulative value, versions. Start a renewal procurement (Start linked procurement): it gets its own number, is linked to the contract and appears in the pipeline, not as a new tender.
2 RatesOpen Rates, escalation and rebates: add a rate "Cleaning hour, $50"; add a scheduled escalation (4% from next 1 July); add a rebate term.
3 SpendFinance (Aisha Rahman) opens the same contract → Spend and invoices: raise a purchase order (100 hours at $50); try a purchase order larger than the contract value to show the spend-ceiling guard blocking it (and keeping a record). Record an invoice at $50 (matched) and one at $55 (blocked: unapproved price increase).
4 ReleaseFinance → Contracts → Invoices: filter Blocked, enter a reason, Release as exception, then Record payment. Back on the contract: progress bars for spend, term, paid and committed; the 70% and fixed 80/90/100% notices.
5 AlertsContract manager → Alerts: the fixed alerts (180/90/60-day countdown, insurance lapse, spend ceiling) cannot be muted; try muting one. Add a custom alert in plain language ("alert me 3 months before expiry and include whoever is my manager") by SMS and Slack (simulated). Alerts from the wording finds notice periods in the clauses.
6 PlansPlans and activities → Generate: contract management plan and risk plan, tier and reasons, scheduled activities; upload your own template.
7 VariationAs Legal, create a variation with a business case; show variance %, who must now sign (tier change), and — if you switch the public-sector setting on in Admin — the register disclosure task (Contracts → Register disclosures).
8 OthersFunding envelopes: the Delegate approves an envelope and nominates Procurement; Procurement commits against it and sees the warning near exhaustion. Master agreements: work orders under a master, reported at both levels.
"A supplier that raises its price, or applies an escalation outside the contract formula, is stopped at the invoice, before the money leaves."

1Executive (Elena Petrova) → Dashboard: KPIs, procurement table, spend by category; then Your role's view. Switch roles to show finance's blocked invoices and the delegate's pending approvals.

9. Questions stakeholders ask

QuestionAnswer
Is the AI real?No. It is deterministic rules behind an adapter (AiProvider), labelled "Simulated AI". The swap point is documented; the target is a model hosted inside the approved region (Amazon Bedrock is the candidate). Every AI result is marked and a person decides.
Where does the data live?Locally in PGlite for the proof of concept; the target is PostgreSQL on AWS. All data in the demo is synthetic.
How is sign-in secured?Passwords hashed with argon2id, lockout, MFA and step-up approvals configurable, session cookies with CSRF protection. The identity provider is a mock behind a swap point; Cognito, Entra ID or Okta are the candidates, with a separate pool for suppliers.
Can a user see something they should not?Authorisation is checked on the server for every operation, tested for every role by a matrix, and sensitive data is protected in the database too (sealed bid files, hidden scores). Refused attempts are audited.
Can the audit trail be altered?It is append-only and hash-chained; a verify command detects any change.
Does it integrate with our ERP, e-signature or email?Not in the proof of concept; each has a defined swap point (docs/swap-points.md). Purchase orders and invoices are entered in the platform to stand in for the ERP feed.
Is it accessible?Built to WCAG 2.1 AA with automated scans on every new screen, keyboard alternatives to drag and drop, and responsive layouts including phone approval.
How much is built?Everything in tiers W and S that can work in a proof of concept is built and traceable on the Roadmap page; tier-D items are explicitly out of scope.
What is left?M16 (documentation, runbook, demo script) and M17 (real-PostgreSQL tests, performance and Lighthouse hardening), then the integration decisions above.

10. If something goes wrong

SymptomCause and fix
Sign-in says "Invalid email or password" with the right passwordThe API on port 4000 is not running. In the terminal stop and run npm run dev.
API will not start and prints "database is out of step"Old database. Stop everything, then npm run db:reset and npm run db:seed, then npm run dev.
Pages say "Internal error", "unavailable" or "could not be loaded"Same as above (stale database) or the API stopped. Check the terminal.
A seeded story is "used up" (for example the evaluation)Reset and seed again: data is synthetic, nothing is lost that matters.
Supplier and staff sessions mixUse a private window for the supplier; sign out first.
Voice dictation does not workUse Chrome or Edge, allow the microphone; otherwise type. The button says when the browser has no support.
Session suddenly endsSessions expire after inactivity; sign in again.
Port 3000 or 4000 already in useAnother dev server is running; close it or restart the machine's node processes.
